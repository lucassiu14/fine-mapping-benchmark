## 0. The question

We run every method over a grid of simulation variables. We want to answer, precisely:

> For each method, which simulation variables drive its performance, in what way,
> and where in the variable space does its behaviour change qualitatively?

"Important" is ambiguous and the ambiguity is load-bearing. We resolve it into
**three distinct questions**, each with its own response variable and its own answer:

| Sense | Question | Response variable |
|---|---|---|
| **V — variance-explaining** | Which variables move this method's metric? | the metric itself |
| **D — decision-relevant** | Which variables change *which method wins*? | the arg-max method |
| **G — diagnostic** | Which variables hurt *this* method beyond making the task hard for everyone? | a paired contrast against a reference method |

These three give genuinely different rankings, and **the disagreements between them are
the scientific content**. A variable can explain 25% of the variance in AUPRC while never
changing which method you would deploy (V high, D zero). A variable can be invisible in
raw AUPRC while dominating how much of the achievable signal a method captures (V zero,
G high). Both patterns occur in this benchmark.

Everything below is computed **within a stratum** (§2.3) and **per method**. There is no
global answer and any global number is invalid — see §9.1.

## 3. From PIPs to the analysis table

Four layers. **Layer 1 is the one that must survive collection** — it is what makes every
downstream statistic re-derivable without re-simulating.

| Layer | Object | Count | Purpose |
|---|---|---|---|
| 0 | raw PIP vectors | ~2.1×10⁹ values | audit / re-derivation only |
| **1** | **per-(cell, method, replicate) sufficient statistics** | 2.34×10⁶ rows | **the pivot** |
| 2 | per-(cell, method) pooled counts + scalars | 2.34×10⁵ rows | rate metrics |
| 3 | per-stratum decomposition inputs | 6 tables | the analysis |

### 3.1 What is computed from the PIPs — the complete list

A **fit** is one method applied to one region in one scenario: a vector of PIPs $p_j$ and
a truth vector $y_j$, both of length $p$ (the region size). **Everything in this document
is a function of these pairs.** The following objects are computed **once per fit**, from
the raw PIPs, and nothing else ever touches raw PIPs again:

| Object | Type | Additive across fits? | Aggregation rule |
|---|---|---|---|
| $\text{AP}$ (§4.1) | scalar | ❌ **no** | **average** |
| $\text{prec@}k$ for $k \in \{1, S, 2S\}$ (§4.6) | scalar | ❌ no | average |
| $\text{set\_size}_\alpha$, $\text{set\_hit}_\alpha$ (§4.6) | scalar / indicator | size ❌, hit ✅ | average size; sum hits |
| $(TP, FP, FN, \Sigma p^{\text{sel}})(t)$ (§4.2) | integer/real vector on a **common** threshold grid | ✅ **yes** | **sum** |
| $(n_b, c_b, \Sigma p_b, \Sigma p^2_b, \Sigma py_b)$ (§4.3) | integer/real vector per bin | ✅ **yes** | **sum** |
| $\text{cs\_coverage},\ \text{cs\_power},\ \text{cs\_size}$ (§4.6) | scalar | ❌ no | average |

**This is the whole reason the fixed threshold grid exists.** Count vectors can only be
summed if they sit on the *same* thresholds; if every fit used its own distinct PIP values
the vectors would have different lengths at different positions and could not be pooled at
all. The grid is mandatory for the FDR curve — and irrelevant to AP, which is a standalone
scalar per fit and is never pooled. See §5.1.

### 3.2 The additivity rule

**Rates are pooled from counts; per-locus scalars are averaged.**

- **AP is a per-locus quantity.** AP of a merged ranked list ≠ mean of the APs, because
  merging lets one region's false positives outrank another region's true positive. A
  pooled ranking describes an analysis nobody performs. → **average, at every level.**
- **FDR and calibration are properties of a population of calls.** "Of all calls made at
  PIP ≥ t, what fraction were wrong" is well posed over calls drawn from many fits. Rates
  computed per fit are unestimable (0–2 selections; bins with $n_b \le 3$).
  → **sum the counts, then form the rate.**

Never average rates, and never pool rankings. Both errors change the answer, not just its
precision.

### 3.3 The aggregation ladder — exactly what happens at each level

| Level | Unit | Contains | AP and per-locus scalars | Counts (FDR, calibration) |
|---|---|---|---|---|
| **L0** | variant | — | — | — |
| **L1** | **fit** = 1 region × 1 method | $p$ variants | **computed here**, from distinct PIPs | **computed here**, on the common grid |
| **L2** | (replicate $i$, `region_size`) | 2 fits | **mean of the 2 fit values** | **sum** the 2 count vectors |
| **L3** | **cell** = (`job`, `S`, `phi`, `region_size`) | 10 L2 units | **mean of the 10**; SE = $\text{sd}/\sqrt{10}$ | **sum** all 20 fits' counts → form the rate |
| **L4** | stratum | cells | ANOVA input — no further aggregation | — |
| — | **anything coarser** | — | ❌ **never** | ❌ **never** |

**Never pooled or averaged across:** `region_size`, `S`, `phi`, any `job`-level factor
(`model`, `p_causal`, `annotation_type`, `enrichment_fold`), or strata.

Two consequences worth stating explicitly:

**(a) Pooling across `region_size` is arithmetically valid but not neutral.** A $p=1000$
region contributes 10× the variants of a $p=100$ region to every bin, so a pooled rate is
dominated by the hardest regions and describes no particular region size. Given that
difficulty scales strongly with $p$ (`susie` AP 0.463 at $p{=}100$ → 0.213 at $p{=}1000$),
this would make region length an uncontrolled confounder inside every FDR and calibration
number. `region_size` stays in the key.

**(b) The SE is computed at L3 from the 10 L2 values, not from the 20 fits.** The 2 regions
inside one replicate share a simulated panel, an annotation draw and an enrichment draw, so
they are *not* independent. Treating 20 fits as 20 replicates would understate the SE.
Average within the replicate (L2), then take the spread across the 10 replicate means.

> **⚠ Current behaviour differs at L2 for AP.** `.stratify_metrics(fits, "region_size", …)`
> groups the 2 same-size fits and `.metrics_for_fits` `unlist`s their PIPs, so AP is
> computed on the **pooled ranking of both regions** — the micro fallacy of §3.2, one level
> down from the one PR #50 fixed. Fix per §5.1b: compute AP per fit and take the mean.

### 3.4 What a replicate actually replicates — the design is split-plot

**A "job" is a row of `params_grid.csv` and does *not* include `S` or `phi`.** Those are
swept inside a job by `run_simulation()` via `expand.grid(S, phi, iter)` = 5 × 5 × 10 = 250
scenarios per job.

Two things are **simulated once per job and shared by all 250 of its scenarios**:

- **Genotypes** — `run_benchmark_job.R:333`, `seed = 1000L + row_idx`, cached in `sim.rds`.
- **Annotation matrices** — `R/run_simulation.R:337`: *"Pre-generate annotation matrices
  (once per region, shared across all scenarios)."*

So an iteration resamples **the causal draw, the effect sizes and the phenotype noise, and
nothing else**. Held fixed across all 10 replicates: the LD structure, which loci were
sampled, the annotation values, and the reference-panel realisation.

**This makes the experiment a split-plot design with three error strata**, not one:

| Stratum | Factors that live here | Replicated? | Error component |
|---|---|---|---|
| **iteration** | `S`, `phi` — vary across scenarios *on the same regions* | ✅ 10 per cell | $\sigma^2_\varepsilon$ |
| **region** | `region_size` — regions differ | ✅ 2 per (job, size) | $\sigma^2_u$ |
| **job** | `p_causal`, `enrichment_fold` | ❌ one panel per job | $\sigma^2_{\text{job}}$ |

A contrast between two levels of `enrichment_fold` compares job A against job B, which drew
**different loci and different annotation matrices**. The measured difference is
(enrichment effect + region-draw difference), and nothing *within* a job separates them,
because within a job the regions never change.

`model` and `annotation_type` are stratifying (§2.3) and `n_ref` is excluded (§2.1), so
**the only job-level factors are `p_causal` and `enrichment_fold`.** Note that
`region_size` occupies the middle stratum in *every* stratum of §2.3, including
`sparse / none`: two levels of `region_size` are always two different region draws, so its
contrasts carry $\sigma^2_u$ even where no job-level factor exists.

> **⚠ Binding constraint on §7.** The iteration variance is the correct noise term for `S`,
> `phi` and their interactions **only**. Every term on the whole-plot margin — `p_causal`,
> `enrichment_fold`, `region_size`, and their mutual interactions — also carries region-draw
> noise, and that noise enters their sums of squares **multiplied by the number of cells
> that share one region draw** ($m = 25$; §7.2). Correcting a whole-plot term with the
> iteration variance alone, or with an unscaled $\hat\sigma^2_u$, understates its noise
> content by two to three orders of magnitude and inflates the apparent importance of
> exactly the factors carrying the annotation conclusions — the classic split-plot error.

### 3.4b The salvage — $\sigma^2_u$ *is* estimable, because `n_ref` is excluded

With `n_ref` dropped, the **only** between-job nuisance is which loci and annotation
matrices were drawn — and that is replicated *inside* a job: 2 regions per size class,
5 size classes, 45 jobs = **225 independent within-job region pairs**, each observed over
10 iterations. (With `n_ref` in the design this would not work: a reference-panel
realisation is drawn once per job and never replicated within it.)

Model at the **fit** level (one method, one stratum), where $r$ indexes region:

$$Y_{g,s,\phi,i,r} = \mu + \text{(fixed effects)} + u_{r(g,\text{size})} + \varepsilon_{g,s,\phi,i,r}$$

$u_r$ is constant across the 10 iterations (the region is literally the same locus), so it
is identified:

1. $\hat\sigma^2_\varepsilon$ — within-region variance across the 10 iterations.
2. $\hat\sigma^2_u = \tfrac{1}{2}\operatorname{Var}\big(\bar Y_{r_1} - \bar Y_{r_2}\big) - \tfrac{\hat\sigma^2_\varepsilon}{10}$,
   where $\bar Y_{r}$ is a region's mean over its 10 iterations and the variance is taken
   over the pairs (pooled across $S$, $\phi$). **Estimate per size class** (45 pairs each),
   not pooled over all 225: $\sigma^2_u$ for a $p{=}100$ draw and a $p{=}1000$ draw are
   unlikely to be equal. Use $\hat\sigma^2_u(g)$ where a per-class value is available and
   the mean $\bar\sigma^2_u$ where a single number is needed (§7.2); report the per-class
   values so the spread is visible.
3. A cell mean averages the 2 regions of its size class, so the job-level nuisance variance
   at cell level is

$$\boxed{\ \hat\sigma^2_{\text{job}} \;\approx\; \hat\sigma^2_u / 2\ }$$

Use that as the whole-plot error for `p_causal` and `enrichment_fold` in §7.3.

Equivalently, fit it directly:

```r
lme4::lmer(Y ~ (fixed effects) + (1 | job:region_size:region_idx), data = fits)
```

**Two assumptions to state when reporting:**

- **A1 — exchangeability.** Regions are exchangeable draws from the VCF pool and
  independent within a job, so a job's panel carries no component beyond its constituent
  region draws. Each region is simulated independently given the job seed, so this is
  reasonable — but it is an assumption, not a verified fact.
- **A2 — no region × scenario interaction.** $u_r$ is taken constant across $S$ and $\phi$:
  the same locus is equally easy at every scenario, relative to other loci. If instead
  $u_{r,s,\phi} = u_r + w_{r,s,\phi}$, the pair-difference estimator absorbs
  $\operatorname{Var}(w)$ into $\hat\sigma^2_u$ — conservative for the whole-plot terms,
  but the subplot terms' correction (§7.2) would then be an *under*-correction.
  **Diagnostic:** compute $\hat\sigma^2_u$ separately per $(S, \phi)$; strong heterogeneity
  means $w \ne 0$.

**Requires per-fit granularity.** The two regions in a size class must be distinguishable,
so the replicate artefact must carry a region identifier — see `combined_fit_metrics.rds`
in §5.5.

**Pooled-rate responses (FDR, calibration) need counts, not per-fit rates.** A per-fit rate
on 0–2 selections is unestimable (§3.2), so for these metrics apply the estimator to
**region-level rates**: pool one region's counts over its 10 iterations (from the L1 count
columns, §5.5), form the rate, and take the pair difference. The sampling-noise term to
subtract is then not $\hat\sigma^2_\varepsilon/10$ but the delete-one-iteration jackknife
variance (§4.5) of the region-level rate. Likewise, the cell-level analogue of
$\sigma^2_\varepsilon/20$ in §7.2 is the delete-one-iteration jackknife variance of the
cell rate, averaged over the stratum's cells.

**Optional confirmation** (not required): re-run 4–6 jobs with `seed = 2000 + row_idx` over
a scenario subset and check that the observed between-panel spread matches
$\hat\sigma^2_u/2$. Cheap, and it converts the assumption above into a measurement.

## 4. Metric definitions

All definitions are over a pooled collection of $N$ variants with $S_{\text{tot}}$ causals.

### 4.1 Ranking: average precision

Selection at threshold $t$: $\mathcal{S}(t) = \{j : p_j \ge t\}$, $n_{\text{sel}}(t) = |\mathcal{S}(t)|$.

$$TP(t) = \sum_{j \in \mathcal{S}(t)} y_j, \quad FP(t) = n_{\text{sel}}(t) - TP(t), \quad FN(t) = S_{\text{tot}} - TP(t)$$

$$P(t) = \frac{TP(t)}{n_{\text{sel}}(t)}, \qquad R(t) = \frac{TP(t)}{S_{\text{tot}}}$$

$$\boxed{\;\text{AP} = \sum_{k} \big(R(t_k) - R(t_{k-1})\big)\, P(t_k)\;}$$

a **step integral**, evaluated over thresholds $t_k$ in *decreasing* order. Linear
interpolation between PR points (the trapezoidal rule) is invalid — the interpolant
describes a classifier no threshold achieves (Davis & Goadrich 2006).

> **AP must be evaluated at the distinct observed PIP values, not on a fixed grid.**
> See §5.1. Using the distinct values makes the estimator (i) exact and (ii) tie-safe by
> construction, and matches `sklearn.metrics.average_precision_score`.

### 4.2 Discovery and FDR

$$\widehat{\text{FDR}}(t) = \frac{FP(t)}{n_{\text{sel}}(t)} \quad (\text{defined as } 0 \text{ when } n_{\text{sel}} = 0)$$

**The guarantee.** If PIPs are calibrated, then among variants selected at threshold $t$,

$$\mathbb{E}[\text{FDR}(t)] = 1 - \mathbb{E}[p_j \mid p_j \ge t] \le 1 - t$$

so the **violation** is

$$V(t) = \max\big(0,\; \widehat{\text{FDR}}(t) - (1 - t)\big)$$

**Self-consistency (new).** The method's own claimed false-positive count among its
selections is

$$\widehat{FP}^{\text{exp}}(t) = \sum_{j \in \mathcal{S}(t)} (1 - p_j) = n_{\text{sel}}(t) - \Sigma p^{\text{sel}}(t)$$

and the **honesty ratio** is $\rho(t) = FP(t) / \widehat{FP}^{\text{exp}}(t)$. This asks the
method to state its own error rate and then scores it, requiring no external theory.
$\rho > 1$ ⇒ more errors than it admits to.

> **Every FDR quantity must be reported with $n_{\text{sel}}(t)$.** A method that selects
> nothing has $\widehat{\text{FDR}} = 0$ by convention and wins every FDR comparison. This
> is not hypothetical: `marginal_z` places zero variants above PIP 0.8 across the entire
> benchmark. **Volume and error are one statistic, not two.**

### 4.3 Calibration

Bins $b = 1..B$ with breaks $0 = e_0 < e_1 < \dots < e_B = 1$. Per bin:

$$n_b = |\{j : p_j \in \text{bin } b\}|, \quad c_b = \sum_{j \in b} y_j, \quad \Sigma p_b = \sum_{j \in b} p_j$$

$$\bar{p}_b = \Sigma p_b / n_b \ \ (\text{predicted}), \qquad \bar{y}_b = c_b / n_b \ \ (\text{observed})$$

**Local calibration** — $\mathbb{E}[y \mid p] = p$:

$$\text{ECE} = \sum_b \frac{n_b}{N}\,\big|\bar{p}_b - \bar{y}_b\big|$$

$\text{ECE}_{\text{hi}}$: the same sum restricted to bins with $e_{b-1} \ge 0.1$, weights
renormalised within that set. **Prefer $\text{ECE}_{\text{hi}}$** — ~94% of all
variant-observations sit in the lowest bin, so plain ECE is overwhelmingly a statement
about how well near-zero PIPs are calibrated and mis-ranks methods.

**Global mass calibration** — $\sum_j p_j = \mathbb{E}[\#\text{causal}]$:

$$M = \frac{\sum_b \Sigma p_b}{\sum_b c_b} \qquad (M = 1 \text{ is correct}; M > 1 \text{ over-confident})$$

**Excess mass by band (new).** For a PIP band $\mathcal{B}$ (union of bins):

$$E_\mathcal{B} = \Sigma p_\mathcal{B} - c_\mathcal{B}$$

Report for $\mathcal{B} \in \{[0,0.1),\,[0.1,0.5),\,[0.5,0.9),\,[0.9,1]\}$. This separates
*harmlessly diffuse* over-confidence (excess spread thinly over nulls) from *confidently
wrong* (excess concentrated in high-PIP calls). No current scalar distinguishes these.

### 4.4 Calibration needs a sharpness companion — the Murphy decomposition

**The problem.** Consider a method emitting $p_j = S/p$ for every variant. With $S=3$,
$p=1000$: $M = 1.000$ (perfect), $\text{ECE} = 0.000$ (perfect), `hi_pip_reliab` = NA
(abstains). **Both headline calibration metrics score a useless predictor perfectly.**
This is the abstention pathology of §4.2 reappearing on the calibration axis.

**The fix.** Use a proper scoring rule and decompose it. With $\bar{y} = \sum_b c_b / N$:

$$\underbrace{\text{BS}}_{\text{Brier}} = \underbrace{\frac{1}{N}\sum_b n_b\,(\bar{p}_b - \bar{y}_b)^2}_{\text{REL — calibration error}} \;-\; \underbrace{\frac{1}{N}\sum_b n_b\,(\bar{y}_b - \bar{y})^2}_{\text{RES — sharpness / discrimination}} \;+\; \underbrace{\bar{y}(1 - \bar{y})}_{\text{UNC — base rate}}$$

- **REL** — lower is better; a squared, proper alternative to ECE.
- **RES** — higher is better; **zero for the uniform predictor**, which is what exposes it.
- **UNC** — a property of the cell, not the method.

**All three terms are computable from bin counts already stored** ($n_b$, $c_b$, $\Sigma p_b$).
This requires *no* collection change — only a change to `.summarise_cell`.

Because UNC varies enormously across cells ($\bar{y} = S/p$ ranges over two orders of
magnitude), raw Brier is **not comparable across cells**. Report the skill score:

$$\text{BSS} = 1 - \frac{\text{BS}}{\text{UNC}} \qquad (1 = \text{perfect},\ 0 = \text{no better than the base rate})$$

**Exact (unbinned) Brier** requires two new accumulator columns:

$$\text{BS}_{\text{exact}} = \frac{1}{N}\Big[\textstyle\sum_j p_j^2 \;-\; 2\sum_j p_j y_j \;+\; \sum_j y_j\Big]$$

i.e. `sum_pip_sq` and `sum_pip_causal` per bin. These also yield the separation statistics
$\overline{p}_{\text{causal}}$ and $\overline{p}_{\text{null}}$.

### 4.5 Aggregation across replicates

For a cell $c$ with $R = 10$ replicates:

**Per-replicate scalars (AP, and every scalar derived from a replicate's own counts):**

$$\hat{Y}(c) = \frac{1}{R}\sum_{i=1}^{R} Y_i(c), \qquad \widehat{\text{SE}}(c) = \frac{\text{sd}_i\{Y_i(c)\}}{\sqrt{R}}$$

**Pooled rates (FDR, calibration):** sum counts over all $R$ replicates, then form the
rate. For their uncertainty use the **delete-one-replicate jackknife**: let
$\hat\theta_{(-i)}$ be the pooled estimate omitting replicate $i$, and
$\bar\theta_{(\cdot)} = \frac{1}{R}\sum_i \hat\theta_{(-i)}$; then

$$\widehat{\text{SE}}_{\text{jack}} = \sqrt{\frac{R-1}{R}\sum_{i=1}^{R}\big(\hat\theta_{(-i)} - \bar\theta_{(\cdot)}\big)^2}$$

This requires per-replicate counts to be retained (§5.5).

### 4.6 Proxies: what the scalars stand in for, and what they discard

**The real objects are curves.** FDR control is a trajectory
$\big(t,\ \widehat{\text{FDR}}(t),\ n_{\text{sel}}(t),\ R(t)\big)$; calibration is a
trajectory $\big(\bar p_b,\ \bar y_b,\ n_b\big)$. The decomposition in §7 needs one number
per cell, so every scalar in the analysis table is a **lossy reduction of a curve**. Which
reduction is a modelling decision, and each one must be justified by what it keeps.

Two rules govern all of them:

> **R1 — Every error-rate proxy must be reported with a volume companion.** FDR ↔
> $n_{\text{sel}}$; reliability ↔ $n$ in the bin; set precision ↔ set size. A method that
> selects nothing scores perfectly on every error rate. `marginal_z` places **zero**
> variants above PIP 0.8 across the entire benchmark and has violation 0.000 everywhere.
>
> **R2 — Prefer the curve evaluated where decisions are made over any global functional of
> it.** A sup-norm or an integral over $[0,1]$ answers "does it ever misbehave anywhere";
> a practitioner asks "what happens at the threshold I use".

#### 4.6.1 Proxies for the FDR curve

| Proxy | Definition | What it discards | Verdict |
|---|---|---|---|
| `max_fdr_violation` | $\sup_t V(t)$ | location, width, whether the worst point is in the operating range; a sup-norm is maximally noise-sensitive | ❌ superseded |
| `max_fdr_violation_n20/n50` | $\sup_{t:\,n_{\text{sel}}\ge n} V(t)$ | same, minus the tail-noise artefact | ⚠️ demote to "does it ever break" |
| `pw_at_fdr05/10/20` | $\max\{R(t) : \widehat{\text{FDR}}(t) \le \tau\}$ | the max runs over a possibly non-contiguous set; one noisy tail point can set it; `NA` conflates *cannot* with *missing* | ✅ keep, guard by $n_{\text{sel}}$, return 0 not NA |
| `viol_argmax_nsel` | $n_{\text{sel}}$ at the unguarded argmax | — | diagnostic only |

**Why the sup-norm is structurally the wrong summary.** The bound is $1-t$: loose at
$t{=}0.5$ (0.5) and tight at $t{=}0.95$ (0.05). Violations are therefore far more meaningful
at high $t$ — and that is exactly where $n_{\text{sel}}$ is smallest and the ratio noisiest.
The statistic systematically reports its own noisiest region. The `_n20` guard is a patch on
a statistic that was measuring the wrong thing. Measured on Iteration 003 (`fb_xregion`,
in-sample): the max is attained at threshold **0.64**, median surviving threshold **0.40**,
and only **4%** of surviving points sit at $t \ge 0.90$. It is a mid-range statistic being
read as a decision-range one — which is why the v2 tuning objective already abandoned it for
FDR@0.95.

**Better proxies.**

**P1 — Point evaluations at the decision thresholds.** `fdr_at_t`, `nsel_at_t`, `tp_at_t`
for $t \in \{0.5, 0.8, 0.9, 0.95, 0.99\}$. Not a proxy at all: the curve restricted to its
operating range. This is the primary FDR summary.

**P2 — Calls-weighted mean violation** (replaces the sup-norm):

$$\bar V_{[t_0,1]} = \frac{\sum_{t \ge t_0} n_{\text{sel}}(t)\,V(t)}{\sum_{t \ge t_0} n_{\text{sel}}(t)}, \qquad t_0 = 0.5$$

A mean is far more stable than a max, and weighting by $n_{\text{sel}}$ builds R1 into the
statistic: an abstainer contributes zero weight everywhere and yields $0/0 = $ `NA` rather
than a perfect score. (One caveat on language: $n_{\text{sel}}(t)$ is cumulative, so a
variant selected at high PIP contributes weight at every threshold below it — the weights
are threshold-exposure, not distinct calls. Fine as a stability weighting; do not describe
$\bar V$ as a per-call average.)

**P3 — Excess false positives, in counts.** The method's own claimed error count among its
selections is $\widehat{FP}^{\text{exp}}(t) = n_{\text{sel}}(t) - \Sigma p^{\text{sel}}(t)$, so

$$\text{ExFP}(t) = FP(t) - \widehat{FP}^{\text{exp}}(t), \qquad \rho(t) = \frac{FP(t)}{\widehat{FP}^{\text{exp}}(t)}$$

Interpretable directly — "this method makes 3.2 more false calls than it admits to". Requires
no external calibration theory: it asks the method to state its own error rate, then scores
it. Zero for an abstainer by construction, which is honest — neither rewarded nor punished.

**P4 — Fixed-$k$ precision.** `prec_at_k` for $k \in \{1, S, 2S\}$. Removes the threshold
entirely. This matters because **methods' PIP scales differ by orders of magnitude**, so any
fixed-threshold comparison partly measures calibration rather than ranking. `prec_at_1` — is
the top-ranked variant causal — is the standard top-SNP accuracy of the fine-mapping
literature and is trivially interpretable.

**P5 — Cumulative-mass sets (uniform "credible set").** For target mass $\alpha$, with PIPs
sorted descending,

$$k_\alpha = \min\Big\{k : \sum_{i \le k} p_{(i)} \ge \alpha\Big\}$$

Report `set_size_95` $= k_{0.95}$, `set_hit_95` $= \mathbb{1}[\exists\,\text{causal in top } k_\alpha]$,
`set_prec_95`. Threshold-free, computable for **every** method from PIPs alone, and
(size, hit) *is* the volume/error pair of R1. This is the practitioner's actual question:
how many variants must I follow up, and will the causal be among them?

**P6 — Propagate the credible-set metrics that are already computed and thrown away.**
`.cs_metrics` ([R/evaluate.R:640](../../R/evaluate.R)) computes `cs_coverage`, `cs_power`,
`cs_size_median/mean`, and `.metrics_for_fits` returns them — but `.summarise_cell` never
carries them into the cell table. Credible-set coverage is the field-standard fine-mapping
evaluation. Available only for methods that emit credible sets, which is precisely why P5 is
needed as the uniform complement.

#### 4.6.2 Proxies for the calibration curve

| Proxy | Definition | What it discards | Verdict |
|---|---|---|---|
| `ece` | $\sum_b \tfrac{n_b}{N}\lvert\bar p_b - \bar y_b\rvert$ | location, direction, **and sharpness**; ~94% of observations are in bin 1 so it mostly scores near-zero PIPs | ❌ do not lead with it |
| `ece_hi` | same, bins with $e_{b-1}\ge0.1$, renormalised | location, direction, sharpness | ✅ keep |
| `mce` | $\sup_b\lvert\bar p_b - \bar y_b\rvert$ | everything but the worst bin; **unguarded**, so a 3-variant bin can set it | ❌ replace with `mce_n20` |
| `signed_bias` | $\sum_b \tfrac{n_b}{N}(\bar p_b - \bar y_b)$ | magnitude/location; but it is the only *direction* statistic | ✅ keep |
| `cal_slope` | $\text{lm}(\bar y \sim \bar p,\ w = n_b)$ | a 10-point regression with **wrong weights** (§5.6b) | ⚠️ fix or replace with §9.4 |
| `total_mass_ratio` | $\sum_j p_j / S_{\text{tot}}$ | **where** the excess sits; gameable by the uniform predictor | ✅ keep — best single number |
| `hi_pip_reliab` | $\bar y$ in the top bin | the entire rest of the curve; **`NA` exactly when the method is most cautious** | ✅ keep, never without `hi_pip_n` |

**Better proxies.**

**Q1 — Murphy REL / RES / UNC and BSS** (§4.4). The principled replacement for ECE: proper
scoring rule, and it separates *calibration* (REL) from *sharpness* (RES). RES = 0 for the
uniform predictor, which is what closes the gaming hole. Computable from the bin counts
already stored.

**Q2 — Excess mass by band** (§4.3). Localises what `total_mass_ratio` states globally.
Distinguishes *harmlessly diffuse* (excess spread thinly over nulls) from *confidently
wrong* (excess concentrated in high-PIP calls) — a distinction no current scalar makes, and
the one that decides whether a miscalibration matters.

**Q3 — Variant-level logit calibration fit** (§9.4). $(\alpha, \beta)$ from
$\text{logit}\Pr(y{=}1) = \alpha + \beta\,\text{logit}(p)$; perfect is $(0, 1)$. A
two-parameter summary of the *whole* curve, no bin boundaries, far more efficient than a
10-point weighted regression.

**Q4 — Mass-ratio dispersion.** `total_mass_ratio` is pooled over the cell, but per region
$\sum_j p_j$ should $\approx S$. Report the SD or IQR of the per-region ratio alongside the
mean: a method uniformly 2× over is fixable by a global rescale; one that is 0.5× on half
its regions and 4× on the other half is not. Currently invisible.

**Q5 — Sharpness, stated directly.** Fraction of total PIP mass above 0.5, and mean PIP
among the top-$S$ ranked variants. Cheap, interpretable, and the mandatory companion (R1) to
any calibration number.

### 5.1 `R/evaluate.R` — stop deriving AP from the FDR curve

**This is not an approximation to be tightened. It is a dependency that should not exist.**

AP is a function of the ranking alone and is computed per fit, then averaged (§3.2) — it is
never pooled, so it never needs thresholds aligned with anything. It should be evaluated at
the distinct observed PIP values, where it is exact by definition.

It currently isn't, because it is read off the FDR curve as a by-product
([R/evaluate.R:377-381](../../R/evaluate.R)):

```r
fdr_power <- .fdr_power_curve(pip_vals, is_causal, pip_thresholds)   # fixed 201-point grid
auprc     <- .compute_auprc(fdr_power$precision, fdr_power$recall)
ap        <- .compute_ap(fdr_power$precision, fdr_power$recall)      # <- reuses that curve
```

`.compute_ap` never sees the PIPs; it only sees (precision, recall) pairs already evaluated
on `pip_thresholds = seq(0, 1, by = 0.005)` ([R/evaluate.R:75](../../R/evaluate.R)).

**The grid is mandatory for the FDR curve and irrelevant to AP.** FDR counts must be summed
across fits and replicates (§3.1), and count vectors can only be added when they sit on the
same thresholds — so a fixed common grid is a hard requirement there. AP has no such
constraint. A grid one metric requires was reused by a metric that does not, and the reuse
imported a bias.

**What the reuse costs.** Within a 0.005-wide band every variant is treated as entering the
selection simultaneously, so a causal is credited with the precision computed *after* every
non-causal in its band has also been admitted. Concretely, a causal at PIP 0.0032 with true
rank 61 of 1000: exact AP $= 1/61 = 0.0164$; grid AP $= 1/1000 = 0.001$, because 0.0032
falls in the band $[0, 0.005)$ and the variant is only captured at $t = 0$, where everything
is selected. In the degenerate case where all PIPs fall below 0.005 the curve collapses to
two points and AP returns roughly the random baseline $S/p$ regardless of the ranking.

**Why this matters more than the measured ~1–5% average.** The error is zero at strong
signal (well-separated PIPs, no collisions) and grows as PIPs compress toward zero.
**It is therefore a `phi`-dependent bias in the estimator of a metric whose `phi` dependence
we are trying to measure.** A constant bias would be harmless; this one contaminates the
`phi` effect in §7 directly.

**Fix.** Compute AP from the distinct observed PIP values. Add to `R/evaluate.R`:

```r
# Exact rank-based average precision. Evaluating at the distinct observed PIP
# values makes this identical to the ranking definition and tie-safe by
# construction (all members of a tied block share one operating point), matching
# sklearn.metrics.average_precision_score.
.compute_ap_exact <- function(pip_vals, is_causal) {
  S <- sum(is_causal)
  if (S == 0L || length(pip_vals) == 0L) return(NA_real_)
  ord  <- order(pip_vals, decreasing = TRUE)
  p    <- pip_vals[ord]
  y    <- as.integer(is_causal[ord])
  last <- c(p[-1L] != p[-length(p)], TRUE)   # TRUE at the end of each tied block
  k    <- which(last)                        # n_selected at each distinct value
  tp   <- cumsum(y)[last]
  prec <- tp / k
  rec  <- tp / S
  sum(diff(c(0, rec)) * prec)
}
```

In `.metrics_for_fits`, replace line 381 with:

```r
  ap      <- .compute_ap_exact(pip_vals, is_causal)
  ap_grid <- .compute_ap(fdr_power$precision, fdr_power$recall)  # legacy, for continuity
```

and add `ap_grid` to the returned list. Keep `auprc` (trapezoid) as-is; it is already
documented as legacy.

> **Do not** implement this as `order()` + precision-at-causal-positions without tie
> handling. Methods emitting many exactly-tied PIPs (e.g. many zeros) would have their AP
> decided by `order()`'s index tie-break, which is genomic position — arbitrary and
> potentially systematic. The block-end formulation above is tie-safe.

.rank_set_metrics <- function(pip, is_causal, alpha = c(0.5, 0.95), S = sum(is_causal)) {
  ord <- order(pip, decreasing = TRUE)
  p   <- pip[ord]; y <- as.integer(is_causal[ord])
  cum <- cumsum(p)
  out <- list(
    prec_at_1  = y[1],
    prec_at_S  = if (S > 0) mean(y[seq_len(min(S,  length(y)))]) else NA_real_,
    prec_at_2S = if (S > 0) mean(y[seq_len(min(2*S, length(y)))]) else NA_real_,
    mass_above_50 = sum(p[p >= 0.5]) / max(sum(p), .Machine$double.eps),
    mean_pip_topS = if (S > 0) mean(p[seq_len(min(S, length(p)))]) else NA_real_
  )

    k <- which(cum >= a)[1L]; if (is.na(k)) k <- length(p)      # never reaches a
    tag <- sub("0\\.", "", format(a))

    out[[paste0("set_prec_", tag)]] <- mean(y[seq_len(k)])
  }
  out
}
```

### 5.5 `collect_results.R` — retain the replicate dimension

**This is the structural change.** Currently the 10 replicates are summed away
(`.acc`, lines 228-243), leaving one number per cell. Consequences:

1. No within-cell noise floor for FDR or calibration ⇒ §7 cannot bias-correct $\omega^2$
   for those metrics, and replicate noise gets laundered into high-order interaction terms.
2. No **paired** SE between methods ⇒ §8.2 flip-gating has no noise estimate.

3. No region identifier ⇒ §3.4b cannot estimate $\sigma^2_u$, so `p_causal` and
   `enrichment_fold` have no valid error term at all.

**Emit three artefacts, one per level of the ladder (§3.3).** With `n_ref` excluded these
are all small.

**(1) `combined_fit_metrics.rds` — L1, one row per (job, S, phi, iter, `region_idx`, method).**
Per-locus scalars **plus per-fit counts** at the decision thresholds and calibration bands.
The counts are what make L1 a genuine pivot: every pooled-rate metric becomes recomputable
at *any* aggregation level (region, iteration, cell) by summing them — which §3.4b needs to
estimate variance components for the rate metrics, not just for AP. Per-fit *rates* are
still never reported (§3.2); only the counts are stored.

```
job_dir S phi iter region_idx region_size method | ap prec_at_1 prec_at_S prec_at_2S
                                                 | set_size_95 set_hit_95 set_prec_95
                                                 | tp_at_{50,80,90,95,99}
                                                 | nsel_at_{50,80,90,95,99}
                                                 | sum_pip_sel_at_{50,80,90,95,99}
                                                 | n_band_{lo,mid,hi,top}
                                                 | c_band_{lo,mid,hi,top}
                                                 | sum_pip_band_{lo,mid,hi,top}
                                                 | n_variants n_causal failed
```

Size: 5,625 cells × 10 iters × 2 regions ≈ 112.5k rows per method, ~1.9M rows over ~17
methods; ~40 numeric columns ≈ 0.6 GB in memory, much less on disk. **`region_idx` (1 or 2
within the size class) is mandatory** — without it the two regions cannot be distinguished
and $\sigma^2_u$ is unidentifiable.

**(2) `combined_replicate_metrics.rds` — L2, one row per (job, S, phi, region_size, method, `iter`).**
Rate metrics from counts pooled over that iteration's 2 regions.

```
job_dir S phi region_size method iter | ap  fdr_at_{50,80,90,95}  nsel_at_{50,80,90,95}
                                      | mass_ratio hi_pip_reliab brier rel res unc
                                      | n_fits n_failed
```

Size: 5,625 × 10 ≈ 56k rows per method, ~956k rows total.

**(3) `combined_scenario_metrics.rds` — L3, one row per cell.** As now, plus the §5.7
columns; keeps the full 201-threshold curve and 26-bin calibration table pooled over all 20
fits.

**The critical property of (1) and (2):** because all methods run on the same simulated data
(common random numbers), the `iter` and `region_idx` indices are **aligned across methods**.
So $d_i = Y_{m_1,i} - Y_{m_2,i}$ is a valid paired difference, and the paired SE is typically
3–10× smaller than $\sqrt{\text{SE}_1^2 + \text{SE}_2^2}$. Storing only means and SEs
destroys this; storing the aligned values preserves it.

fit <- stats::lm(fc ~ mp, weights = n[keep])
```

$\bar{y}_b$ is a binomial proportion with variance $\bar{y}_b(1-\bar{y}_b)/n_b$, so the
correct weight is $n_b / (\bar{y}_b(1-\bar{y}_b))$, not $n_b$. With ~94% of mass in the
lowest bin at $\bar{y} \approx 0.003$ this is not a marginal difference. Either fix the
weights (clamping $\bar{y}_b(1-\bar{y}_b)$ away from 0) or replace the 10-point regression
with a variant-level logistic fit (§8.4).

**(c) Failure counts never reach the analysis table.** `.metrics_for_fits` computes
`n_fits` and `n_failed` (lines 405-406) but `.summarise_cell` drops them. A cell where
half the fits errored yields metrics computed on the survivors, indistinguishable from a
clean cell. Given `funmap` fails 100% on the `none` arm and `carma` failed 100% for three
iterations, propagate both as columns.

**(d) `pw_at_fdr*` conflates "cannot" with "missing."** Line 301 returns `NA_real_` when
no threshold achieves the target FDR. That is a *result* (the method never reaches FDR
≤ 0.05), not missing data, and `NA` will be dropped by every downstream aggregation.
Return `0` and add a separate `pw_at_fdr05_achievable` logical.

## 7. Sense V — variance-explaining

### 7.1 Two fits with two jobs

Within one stratum, one method, one response $Y$, with free factors $F_1..F_K$
($K = 3..5$), the analysis needs two things, and they come from two different fits:

**(a) The variance components, from L1.** Fit the §3.4b model on the fit-level table —

```r
vc <- lme4::lmer(Y ~ F1 * F2 * F3 * F4 * F5
                   + (1 | job_dir:region_size:region_idx),
                 data = fits_stratum_method)
```

— or use the §3.4b moment estimators, which need no model fit. Either way this yields
$\hat\sigma^2_\varepsilon$ (iteration noise; for sparse/binary the residual has thousands
of df, so it is pure replicate error, not confounded with unmodelled interactions) and
$\hat\sigma^2_u(g)$ (region draw, per size class). For pooled-rate responses use the
count-based route in §3.4b.

**(b) The sum-of-squares decomposition, from the L3 cell-mean table.** Within a stratum
the design is complete and balanced, so the full factorial on the cell means

```r
fit <- aov(Y_bar ~ F1 * F2 * F3 * F4 * F5,
           data = cells_stratum_method)     # one row per cell; zero residual df
```

gives orthogonal, order-independent $SS_T$ that partition the total exactly:
$\sum_T SS_T = SS_{\text{tot}}$. There is deliberately no residual line — every df belongs
to a term, and noise is handled by explicit *correction* (§7.2), never by a residual.

Balance matters for the closed forms below: they assume 20 fits in every cell. Verify with
`n_fits` / `n_failed` (§5.6c); a method with material failure rates gets the `lmer` route,
not the closed forms.

> **Why not one replicate-level ANOVA with a different $MS_E$ per term?** Because the two
> noise sources live at different levels of aggregation, and each enters a replicate-level
> mean square **multiplied by the number of rows that share the draw** (hundreds, here).
> Subtracting a cell-mean-scale $\hat\sigma^2_u/2$ from a replicate-level mean square
> under-corrects by two to three orders of magnitude — it looks compliant with §3.4 while
> silently recreating the inflation §3.4 warns about. Working on cell means keeps every
> quantity on a single scale, where the correction has a closed form (§7.2).

### 7.2 The noise correction $\lambda_T$, and the variance budget

A cell mean is $\bar Y_c = \mu_c + \eta_c$, and by §3.4 its estimation noise has exactly
two parts: $\eta_c = \bar u_{j(c),\,g(c)} + \bar\varepsilon_c$, where
$\bar u = (u_{r_1} + u_{r_2})/2$ is the averaged region draw of the cell's
(job, `region_size`) block and $\bar\varepsilon_c$ is the averaged iteration noise:

$$\operatorname{Var}(\bar u) = \sigma^2_u/2, \qquad \operatorname{Var}(\bar\varepsilon_c) = \sigma^2_\varepsilon/20$$

The two behave differently across cells: $\bar\varepsilon_c$ is independent across all
cells, while $\bar u$ is **shared by the $m = 25$ $(S,\phi)$-cells of one block** — it is,
in effect, a random factor living on the (job-level factors × `region_size`) margin. Call
that margin the **whole-plot margin** $\mathcal{W}$: every term composed only of job-level
factors and/or `region_size`. On a balanced design the expected noise content of each
term's SS then has a closed form:

$$\mathbb{E}[SS_T] = SS_T^{\text{true}} + df_T\,\lambda_T, \qquad
\boxed{\;\lambda_T = \frac{\sigma^2_\varepsilon}{20} + \frac{m\,\sigma^2_u}{2}\,\mathbb{1}\big[T \in \mathcal{W}\big]\;}$$

The factor $m$ is the whole point: $\bar u$ is constant across the $(S,\phi)$ sweep, so its
variance enters a whole-plot term's mean square multiplied by the $m = 25$ cells sharing
it. Any term containing $S$ or $\phi$ annihilates $\bar u$ exactly — its contrasts sum to
zero within each block — leaving only the iteration term. (Worked check, sparse/binary,
$T = \texttt{enrichment\_fold}$: each level mean averages 125 cells, so its noise variance
is $\sigma^2_u/(2\cdot 5) + \sigma^2_\varepsilon/(20 \cdot 125)$; multiplying by the 125
cells per level gives $25\sigma^2_u/2 + \sigma^2_\varepsilon/20$ per df. ✓ The same value
comes out for `region_size` and for whole-plot interactions, so $\lambda$ is uniform on
$\mathcal{W}$.)

The budget is then a single identity — replacing the earlier replicate-level version, which
hid the region-draw noise inside the whole-plot terms' SS:

$$1 = \underbrace{\sum_T \frac{SS_T - df_T\,\lambda_T}{SS_{\text{tot}}}}_{\text{structure, term by term}} \;+\; \underbrace{\frac{\sum_T df_T\,\lambda_T}{SS_{\text{tot}}}}_{\text{noise floor}}$$

It holds algebraically (the terms sum to $SS_{\text{tot}}$), and each corrected share is
unbiased for its true-surface counterpart up to the plug-in $\hat\lambda$ and the ratio
nonlinearity. Report the noise floor split into its iteration and region-draw parts, and
aggregate the structure shares by interaction order (mains / 2-way / 3-way+).

**This bounds every subsequent claim.** If the noise floor is 50%, no factor decomposition
can explain more than half. If main effects dominate, marginal plots are honest summaries;
if 2-way+ dominates, every claim must be conditional.

### 7.3 The two importance numbers

Report **both** per factor — they answer different questions and can disagree.

**(i) Noise-corrected variance share.** With $\lambda_T$ from §7.2:

$$\omega^2_T = \frac{SS_T - df_T\,\lambda_T}{SS_{\text{tot}}}$$

The per-term $\lambda_T$ *is* the split-plot error-stratum discipline of §3.4, on the
correct (cell-mean) scale: `S`/`phi` terms shed only iteration noise; every term on the
whole-plot margin — `p_causal`, `enrichment_fold`, `region_size` and their mutual
interactions — additionally sheds $m\,\sigma^2_u/2$ per df. In `sparse / none` the
whole-plot margin is just `region_size`: that stratum is the simplest, not
correction-free.

Three practical rules:

- **Do not clamp negative values.** $\omega^2_T$ can go below zero for null factors;
  report it as computed. Many strongly negative shares mean $\hat\lambda$ is too large —
  a diagnostic, not an embarrassment.
- **Heteroscedastic $\sigma^2_u$:** use $\bar\sigma^2_u$ (the mean over size classes,
  §3.4b) in $\lambda_T$. This is exact for whole-plot terms that average over
  `region_size` and first-order for terms containing it; the per-class estimates
  $\hat\sigma^2_u(g)$ show how much that approximation matters.
- $\omega^2_T$ is a share of the **observed** cell-mean SS, so the shares and the noise
  floor sum to 1 (§7.2). When comparing across strata or metrics whose noise floors
  differ, use the true-surface (Sobol) normalisation
  $\pi_T = \omega^2_T / (1 - \text{noise floor})$.

Use $\omega^2$, **not** $\eta^2$. Factors here have 1–4 df; a higher-df factor mechanically
captures $df_T\,\lambda_T$ of noise. The subtraction removes exactly that, which is
required for comparability across factors with different level counts.

**(ii) Effect span, in metric units.**

$$\text{span}_i = \max_{l \in L_i} \bar{Y}_{F_i = l} \;-\; \min_{l \in L_i} \bar{Y}_{F_i = l}$$

df-free, directly interpretable ("moving from best to worst level costs 0.18 AUPRC"), and
immune to the level-count artefact.

Disagreements are informative: large span with small $\omega^2$ ⇒ the effect is
concentrated in one extreme level; large $\omega^2$ with small span ⇒ finely graded.

**(iii) The interaction diagnostic.** First-order and total-order indices:

$$S_i = \frac{V_i}{V}, \qquad S_{T_i} = \frac{\sum_{U \ni i} V_U}{V}, \qquad S_{T_i} - S_i = \text{interaction involvement}$$

On a balanced complete grid these are exactly the ANOVA variance shares — no Monte Carlo
estimator needed. Compute them from the **corrected** components,
$V_U = SS_U - df_U\,\lambda_U$ with $V = \sum_U V_U$ (equivalently from $\pi_T$), so that
a noisy high-order term is not read as interaction structure. $S_{T_i} - S_i \approx 0$ ⇒
the factor acts additively and its marginal plot tells the whole story. Large ⇒ its effect
is conditional and the marginal is misleading.

### 7.4 Ordered factors: use polynomial contrasts

`S`, `phi`, `region_size` and `enrichment_fold` are all ordered. Set
`contrasts(d$phi) <- contr.poly(5)` and partition the 4 df into linear / quadratic /
cubic / quartic. "AP falls linearly in $\log \phi$ at $\beta$ per doubling" is a stronger
and more portable claim than "the five levels differ", and costs 1 df instead of 4.
Polynomial contrasts partition $SS_T$ into single-df components, and each component
inherits the same per-df correction: subtract one $\lambda_T$ from each.

### 7.5 Mandatory caveats on every reported importance number

1. **Range dependence.** $\omega^2$ is defined relative to the input distribution, which
   here is uniform over the chosen levels. Widening a factor's range mechanically inflates
   its importance. The honest statement is always *"X explains 34% of variance over the
   range swept"*, never *"X is the most important factor"*.
2. **Uniform weighting.** Marginal means weight every combination of the other factors
   equally. If deployment concentrates in some corner, reweight (weighted group means) —
   it can substantially reorder the ranking.
3. **Metric scale.** $\omega^2$ is not invariant to monotone transforms of $Y$. Bounded
   metrics saturate: a factor operating where AP ≈ 0.98 will look unimportant because
   there is no room to move. For bounded rates decompose on the logit scale, or relativise
   per cell (§9).

### 7.6 Repeat for all three metrics

Run §7.1–7.4 three times: $Y \in \{\texttt{ap},\ \texttt{fdr\_at\_90},\ \texttt{bss}\}$
(or `hi_pip_reliab` / `total_mass_ratio`). Different factors will top each list. **That
disagreement is a finding**, not an inconsistency — it is the formal version of "this
method's ranking is fine but its calibration is broken."

## 8. Sense D — decision-relevant

### 8.1 The decision

Let $\mathcal{M}_{\text{prac}}$ = all methods **excluding** `polyfun_oracle` (a ceiling, not
a deployable competitor). Define per cell:

$$W(c) = \operatorname*{arg\,max}_{m \in \mathcal{M}_{\text{prac}}} \hat{Y}_m(c)$$

Optionally also $U(c) = \mathbb{1}[\hat{Y}_m(c) > \tau]$ ("is this method usable at all"),
which can be decomposed with the §7 machinery directly as a binary response.

### 8.2 Flip rate

For factor $F$ with levels $L_F$, let $\mathcal{C}_{-F}$ be the set of combinations of all
*other* free factors in the stratum:

$$\boxed{\;\phi_F = \frac{1}{|\mathcal{C}_{-F}|}\sum_{c_{-F} \in \mathcal{C}_{-F}} \mathbb{1}\Big[\,\big|\{\,W(c_{-F}, F{=}l)\ :\ l \in L_F\,\}\big| > 1\,\Big]\;}$$

Hold everything else fixed, sweep $F$, ask whether the winner changed, average over all
settings of the others. In sparse/binary with $F = \texttt{enrichment\_fold}$ there are
$500/4 = 125$ such settings.

### 8.3 Gating — mandatory

An ungated flip rate counts coin tosses as findings. A change of winner is **real** only
if the margin exceeds the noise. Using the replicate-level table (§5.5), for the top two
methods in a cell compute the **paired** difference per replicate:

$$d_i(c) = Y_{m_{(1)},i}(c) - Y_{m_{(2)},i}(c), \qquad \widehat{\text{SE}}_{\text{paired}}(c) = \frac{\text{sd}_i\{d_i(c)\}}{\sqrt{R}}$$

Count a flip only where $|\bar{d}(c)| > z\,\widehat{\text{SE}}_{\text{paired}}(c)$ at every
level of $F$ (use $z = 2$); otherwise mark the cell *undecided* and exclude it from the
denominator. **Report the raw and gated rates side by side** — the gap quantifies how much
apparent decision structure is noise.

Because all methods see the same simulated data, the paired SE is the correct one and is
3–10× smaller than $\sqrt{\text{SE}_1^2 + \text{SE}_2^2}$. Using the unpaired form
discards most of the available power.

**Do not select and test on the same replicates.** $W(c)$ is an arg-max over noisy means,
so the winner's margin over the runner-up is biased upward when measured on the replicates
that chose it (winner's curse) — the gate as stated above is anti-conservative in exactly
the marginal cells it exists to police. Cross-fit: split the 10 replicates into halves A
and B; identify the top two on A and test $|\bar{d}| > z\,\widehat{\text{SE}}_{\text{paired}}$
on B (5 replicates, so the sd is over 5 and the divisor $\sqrt{5}$); then swap the roles
and count the cell as *decided* only if **both** directions decide it with the same winner.
Report the full-sample $\bar d$ for decided cells — the split governs only the
decided/undecided call, not the reported effect size.

### 8.4 The regime map

Take the two or three factors with the highest gated flip rates and tabulate the modal
winner over their cross-product, marginalising the rest:

```
                S=1            S=3           S=10
phi=0.0075      <method>       <method>      <method>
phi=0.05        <method>       <method>      <method>
...
```

This is the direct answer to "when does each method do well" and is normally the single
most communicative figure in the analysis. A regime map lives **within one stratum** — its
axes are free factors of that stratum, never `model`, `annotation_type` or `n_ref`.

## 9. Sense G — diagnostic

### 9.1 Why raw metrics cannot answer this

A factor affects a method's score in two ways that raw score confounds:

- it makes the problem **harder for everything** (a property of the task);
- it makes **this method specifically** worse (a property of the method).

The factor with the largest $\omega^2$ on raw AP is usually just the difficulty knob.
Reporting it as a finding *about the method* is the error this section exists to prevent.

### 9.2 Paired contrasts

Reshape wide by method within a cell (all methods share the simulated data, so these are
exact paired quantities), then define:

$$\text{headroom}(c) = Y_{\texttt{polyfun\_oracle}}(c) - Y_{\texttt{susie}}(c)$$

$$\boxed{\;\kappa_m(c) = \frac{Y_m(c) - Y_{\texttt{susie}}(c)}{Y_{\texttt{polyfun\_oracle}}(c) - Y_{\texttt{susie}}(c)}\;}$$

— the fraction of the **available annotation headroom** that method $m$ captures. This is
the systematised form of the Iteration 001 finding that pooled S-LDSC captured 3% of the
gap at $\phi = 0.0075$ and 24% at $\phi = 0.4$.

Controlled pairs (annotation use is the only difference):

$$\Delta^{\text{annot}}(c) = Y_{\texttt{functional\_beatrice}}(c) - Y_{\texttt{beatrice}}(c)$$
$$\Delta^{\text{joint}}(c) = Y_{\texttt{fb\_xregion}}(c) - Y_{\texttt{functional\_beatrice}}(c)$$

**Gate $\kappa$ on headroom:** it is unstable when the denominator ≈ 0. Require
$\text{headroom}(c) > \epsilon$ (e.g. 0.02) and **report the excluded fraction** — the
cells where the ceiling has collapsed are themselves a finding, not a nuisance.

### 9.3 The difficulty-vs-sensitivity table

Run the identical §7 decomposition on $\kappa$ and on $\Delta$, then place the results
beside the raw-metric decomposition:

| Factor | $\omega^2$ on $Y$ | $\omega^2$ on $\kappa$ | Reading |
|---|---|---|---|
| high | ~0 | | **difficulty knob** — hard for everyone; says nothing about this method |
| ~0 | high | | **method-specific weakness** — the thing to fix |
| high | high | | genuinely hard *and* handled badly |
| ~0 | ~0 | | irrelevant over the range swept |

This table is the payload of sense G.

For the $\kappa$ and $\Delta$ decompositions, the §7.2 correction needs *their* variance
components, not the raw metric's: compute $\kappa$ (or $\Delta$) at replicate level — all
methods share replicates, so the paired quantity is exact there too — and run §3.4b on the
result, gating replicate-level $\kappa$ on replicate-level headroom exactly as in §9.2.

### 9.4 Optional: variant-level calibration regression

For calibration specifically there is a legitimate way to use the PIPs without binning:

$$\text{logit}\,\Pr(y_j = 1) = \alpha + \beta\,\text{logit}(p_j) + \sum_k \gamma_k \big(F_k \times \text{logit}(p_j)\big)$$

Perfect calibration is $\alpha = 0$, $\beta = 1$. The interaction terms $\gamma_k$ say
directly how calibration degrades along each factor, with no bin boundaries and far more
power. Subsample variants — the full ~2.1×10⁹ is unnecessary. This **complements** §4.3–4.4;
it does not replace AP (a ranking quantity with no variant-level analogue) or the FDR
curves (a property of a selection rule).

## 10. Subpatterns

Once the three responses exist:

1. **Crossover screen.** For each active factor pair, test whether the effect of $A$
   *reverses sign* across levels of $B$. Quantitative interactions (magnitude varies) are a
   nuisance; qualitative ones mean the marginal claim about $A$ is **wrong**, not merely
   imprecise. Same mechanism as the never-pool rule, operating between factors instead of
   across strata. Screen systematically; do not rely on spotting them in plots.
2. **Bump hunting.** Run PRIM (Friedman & Fisher 1999) or a depth-≤4 `rpart` separately on
   each response. On $\kappa$ it finds "where this method loses ground it should have
   captured"; on $Y$ it finds "the hard region"; on $W$ it finds "where the winner
   changes". Three separately reportable findings from one tool. PRIM is preferable to a
   tree because it returns the coverage/extremity trajectory so the trade-off is an
   explicit choice.
3. **Failure as its own response.** Define a binary indicator (`n_failed > 0`, or
   `hi_pip_reliab < 0.5`, or `honesty_ratio_at_90 > 2`) and decompose *its* probability.
   Which factor combinations produce outright breakage is usually crisper than which shift
   the mean.
4. **Profile clustering.** Cluster methods by their $Y$ vector across all cells in a
   stratum. Co-clustering methods are redundant over this design; the axis separating
   clusters names the mechanism. (Known: on `none` arms `polyfun_est` ≡ `polyfun_ldsc` ≡
   `susie` exactly — a correctness check, and a warning that win-rates among them are pure
   tie-breaking.)

## 11. Validity checks — run before believing anything

| Check | Procedure | Failure means |
|---|---|---|
| **Noise floor** | §7.2 budget identity | if the noise floor is large, cap all claims accordingly |
| **Correct noise correction** | §7.2 — is the term on the whole-plot margin? then $\lambda_T$ must include $m\,\sigma^2_u/2$ | correcting a whole-plot term with iteration noise alone inflates its importance by orders of magnitude |
| **Split-half stability** | split **by replicate**, not by cell; recompute all three rankings | unstable top-3 ⇒ reporting noise |
| **Held-out level** | drop one level of a factor, refit, predict it | poor prediction ⇒ interpolation, not structure |
| **Multiplicity** | gate hierarchically: test interactions only among factors whose mains survived | flat BH over $2^K$ terms is far less powerful |
| **Effect sizes only** | never report $p$-values | at thousands of rows everything is significant; $p$ carries no information |
| **Null claims** | "no effect of $F$ exceeding $\delta$ over range $R$, powered to detect $\delta$" | untested ≠ tested-and-null |
| **Sanity anchors** | `abf` mass ratio must equal $1/S$ exactly; `susie` AP ≈ equal on binary vs continuous | pipeline is broken |

## 12. Known data-validity constraints

These are properties of the existing runs, not of the method. Any analysis of
Iterations 001–003 must respect them.

| Constraint | Effect |
|---|---|
| **PAINTOR was run per-locus** in Iterations 001–003 | its EM estimates enrichment across all loci in one `-input` file — that is the mechanism. Every PAINTOR verdict in those iterations is **invalid**. Fixed (`run_paintor_scenario_setup` pools, z-fingerprint keyed) but **not re-run**. Exclude PAINTOR or re-run before including it. |
| **`carma` was never installed** for Iterations 001–003 | 100% NA. Now installed. Absent, not zero. |

| **`ap` in `combined_scenario_metrics.rds` is micro** unless the file is `combined_scenario_metrics_macroAP.rds` or the run post-dates PR #50 | micro understates AP most at low $S$ (0.547 → 0.600 at $S{=}1$), i.e. an $S$-dependent bias in a factor being decomposed |

| **`fb_pooled` is superseded** | Iteration 003 showed the linear prior head loses ranking on binary (AUPRC better in only 6–23% of cells). Drop it from decision analysis. |

## 13. Execution order

1. Apply §5.1–5.4 (`R/evaluate.R`), §5.6 (`.summarise_cell` fixes), §5.7 (new columns).
2. Add the §5.8 tests; they must pass before any re-collect.
3. Re-collect from the stored PIPs. Re-reads `results.rds` / `evaluation.rds` — no refitting
   — and produces the three artefacts of §5.5, **including `region_idx`**.
4. **Filter to in-sample LD on the raw `NA`, then recode NA-as-level** (§2.1, §6 — in
   that order, before anything else). `d <- d[is.na(d$n_ref), ]` → 45 jobs, 5,625
   cells/method. Assert the row count.
5. Fix the method set explicitly (§2.5). `carma` / `finimom` / `finemap_inf` / corrected
   `paintor` are absent until Iteration 004; state which set was used.
6. Estimate the variance components $\hat\sigma^2_\varepsilon$ and $\hat\sigma^2_u(g)$
   from `combined_fit_metrics.rds` (§3.4b) — per size class, and via the count columns for
   the rate metrics. **Before any $\omega^2$.**
7. Per stratum (6) × method: budget identity (§7.2), then $\omega^2$ + span + $S_T - S_1$
   (§7.3) for each of the three metrics, **using the per-term correction $\lambda_T$**.
   Develop on `sparse / none` first — no job-level factors, though `region_size` still
   takes the $m\,\sigma^2_u/2$ correction.
8. Per stratum: winner map, flip rates raw + gated (§8), regime map.
9. Per stratum × focus method: $\kappa$ and $\Delta$ decompositions, difficulty-vs-
   sensitivity table (§9.3).
10. Subpatterns (§10) on each response.
11. Validity checks (§11). Nothing is reported before these pass.

**Every claim produced under this spec is conditional on in-sample LD** and must say so.
Iteration 002 established that in-sample and reference-panel LD invert method rankings, so
none of these conclusions transfer to the panel setting.
